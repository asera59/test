## 1. 链一：你写的东西，是怎么变成芯片动作的

四个环节，缺一个都不成立：

```
  你写 main.c          编译器 Build          芯片逐条执行          Watch 窗口
  （人能读懂的文字） → （翻成芯片认的 0/1） → （没板子用仿真器） → （看变量有没有变）
```

### 1.1 为什么必须有 `main`

芯片上电复位后，只知道去一个固定地址取第一条指令。`main` 是 C 语言约定好的**起点**：程序从这里开始，一行一行往下走。

- 不这么做会怎样：没有入口，编译器不知道把程序的开头放在哪里，直接报错或生成的程序根本不运行。

### 1.2 为什么要编译（Build），为什么建工程要选器件型号

芯片只认高低电平（0 和 1），不认英文字母。`Build` 是翻译官，把 C 翻译成芯片认的机器码（`.hex` 文件）。

**选器件型号是告诉翻译官"翻给谁听"**：不同芯片的寄存器地址、指令集不一样。你选 STC15F2K60S2，它才知道 `P0` 对应哪个地址、`0x80` 这个数送到哪里去。

- 不这么做会怎样：翻译成别的芯片的语言，烧进去灯就是不亮，而且**不报任何错**——这是最难查的一类问题。

### 1.3 仿真器是什么（板子 10/8 才到，这段时间全靠它）

Keil 自带 Simulator，它在电脑里**假装一块芯片**，一样会一条条执行你的指令。

唯一区别：**它不输出真实电压**，只是把寄存器里的数字显示给你看。所以你看到的是"P0 寄存器的值变成了 0xFE"，而不是"灯亮了"。

- 为什么这够了：因为 LED 亮不亮，本质上就是看 P0 的那一位是不是 0。能把寄存器写对，真机上就一定能亮。

### 1.4 Watch 窗口为什么重要

程序跑起来你是看不见的。Watch 窗口就是**把芯片内部的抽屉拉开给你看**：你告诉它想看哪个变量，它就实时显示那个变量的值。

- 怎么验证前三环全通：在 Watch 里加上 `i`，如果 `i` 每循环一圈就 +1，说明 写代码 → 编译 → 执行 三环都通了。

### 1.5 今天那 7 行，每行对应哪一环

```c
#include <reg52.h>       // 给编译器一本词典：P0、P2 这些名字对应哪个地址
void main(void)          // 入口：芯片复位后从这里开始（1.1）
{
    unsigned char i = 0; // 在芯片里申请一个 8 位的盒子，取名 i（第 2 节）
    while (1) {          // 死循环：把程序拴住，不让它跑飞（第 3 节）
        i = i + 1;       // 每圈加 1 —— 这是你能在 Watch 里看见的东西（1.4）
    }
}
```

## 2. 芯片里的盒子：变量、数据类型与十六进制

### 2.1 为什么端口操作一律用 `unsigned char`

51 单片机的寄存器是 **8 位**的。`unsigned char` 正好也是 8 位（取值 0–255），一个萝卜一个坑。

- `int` 在 51 上是 **16 位**，占两个字节。拿它去给 8 位端口赋值，高 8 位白白浪费，还容易出错。
- 不这么做会怎样：不会立刻报错，但代码在 51 上又慢又占内存，而且与端口宽度不匹配时行为难以预测。

### 2.2 `0xFE` 怎么读

`0x` 是**前缀**，表示"后面这串数字是十六进制"，它本身不是数值的一部分。

- 十六进制的数字是 `0-9` 和 `A-F`（A=10、B=11、C=12、D=13、E=14、F=15）
- `0xFE`：F 在 16 位（高位）、E 在 1 位（低位）→ `15 × 16 + 14 = 254`
- 换算成二进制：**每 1 个十六进制位 = 4 个二进制位**，所以 `F`=`1111`、`E`=`1110`，拼起来就是 `1111 1110`

| 十六进制 | 二进制 | 十进制 |
| --- | --- | --- |
| `0x0F` | `0000 1111` | 15 |
| `0xF0` | `1111 0000` | 240 |
| `0xFE` | `1111 1110` | 254 |
| `0x80` | `1000 0000` | 128 |

**为什么单片机里都用十六进制**：8 位二进制写成十六进制只要 2 个字符（`1111 1110` → `0xFE`），而且**看 `FE` 就能一眼看出位模式**——最低位是 0，其余是 1。写成十进制的 254，你根本看不出哪一位是 0。这就是嵌入式代码里满屏十六进制的原因。

**关键在于看每一位**：`1111 1110` 的最低位是 0，其余是 1，所以只有第一颗 LED 亮。

### 2.3 为什么是"0 亮 1 灭"

CT107D 上的 LED 是**共阳**接法：LED 的阳极接电源，阴极经锁存器接到 P0。

所以 **P0 输出 0（低电平）时，电流才能流过，灯才亮**；输出 1 时两端都是高电平，没有压差，灯灭。

- 因此 `P0 = 0xFE` 的效果是：**只有最低位对应的那颗 LED 亮**，其余 7 颗灭。
- 不弄明白这一点会怎样：你会写出"想点亮却写 0x01"的代码，然后对着不亮的灯怀疑人生。

## 2.4 数组与"遍历"

**数组**：一排连续的盒子，用**编号**取用，编号从 **0** 开始。

```c
unsigned char led[4] = {0xFE, 0xFD, 0xFB, 0xF7};
/*            led[0] led[1] led[2] led[3]      */
```

**遍历**：用循环把数组**从头到尾访问一遍**。

```c
int i;                                  /* C90：先声明 */
for (i = 0; i < 4; i++)                 /* 从 0 开始，i < 4 → 正好 4 次 */
{
    printf("%d ", led[i]);              /* i 变化 → 每次访问不同的盒子 */
}
```

**为什么必须有循环**：数组里有几个元素，就要处理几次。手工写 `led[0]; led[1]; led[2]; led[3];` 在 4 个元素时还行，100 个元素就是 100 行，而且元素个数一变，全都要改。

**这里最值钱的一点**：`led[i]` 里的 `i` 是**变量**——循环让它从 0 变到 3，于是同一行代码访问了四个不同的盒子。**"下标可以是变量"是数组的灵魂**，也是后面学指针的入口。

**为什么写 `i < 4` 而不是 `i <= 3`**：两者结果一样，但 `i < 元素个数` 的写法在个数变化时不容易数错，是行业惯例。

## 3. 为什么单片机程序必须 `while (1)`

这是单片机程序和你在电脑上写 C **最大的区别**。

电脑上 `main` 跑完，程序退出，回到桌面。芯片**没有桌面**：`main` 跑完之后，它会继续往下读内存里的内容——而那里是乱码，于是程序**跑飞**（行为完全不可预测，可能乱输出、可能死机）。

所以必须用 `while (1)`（条件永远为真）把它拴住，让它一直干活直到断电。

- 不这么做会怎样：程序执行一次就跑飞。典型症状：灯闪一下就不动了，或者行为毫无规律。

## 4. 位运算：为什么玩单片机离不开它

端口的每一位都对应一个物理引脚，所以你要经常"只改某一位、别的位不许动"。这就是位运算存在的理由。

| 运算符 | 作用 | 单片机场合的典型用法 |
| --- | --- | --- |
| `&` 与 | 两位都为 1 才得 1 | **清零**某些位（与 0 相与） |
| `\|` 或 | 有一位为 1 就得 1 | **置 1** 某些位 |
| `~` 取反 | 0 变 1、1 变 0 | 生成掩码 |
| `^` 异或 | 不同为 1 | 翻转某些位（LED 闪烁） |
| `<< >>` 移位 | 整体左移/右移 | 生成流水灯序列 |

### 4.1 `P2 & 0x1F` 为什么是"保留低 5 位"

`0x1F` = 二进制 `0001 1111`。任何数和它相与：

- 低 5 位与 `1` 相与 → **保持原样**
- 高 3 位与 `0` 相与 → **全部清零**

所以要改 P2 的高 3 位（用来选通 74HC138），先 `& 0x1F` 把高 3 位清干净，再 `| 0x80` 设成想要的值，就不会误伤其他位。

- 不这么做会怎样：直接写 `P2 = 0x80` 会把低 5 位全部清零，可能把别的外设状态一起改掉。

### 4.2 五个手算练习（对照 9/22 主线一任务）

1. `0x01 << 3` = ?
2. `0xF0 | 0x0F` = ?
3. `~0x0F` = ?（注意结果是 8 位还是 16 位）
4. `P2 = 0x35; P2 & 0x1F` = ?
5. 要让 `0xFE` 的最低位变 1，该用 `|` 还是 `&`？写出表达式。

## 5. 链二：引脚不够用怎么办（你这块板子最难、也最值钱的部分）

**问题**：芯片引脚有限，可 LED、数码管、蜂鸣器都要用 8 根数据线。怎么办？

**解法**：让它们**共用 P0 口**，靠 74HC138 选通 + 74HC573 锁存来分时复用。

```
P2.5 P2.6 P2.7 ──→ 74HC138 ──→ Y4 / Y5 / Y6 / Y7 ──→ 74HC573 ──→ P0 口 ──→ LED
（3 根线选通道）    （3-8 译码）  （选中一个外设）      （锁住数据）   （8 位数据）  数码管
                                                                                   蜂鸣器
```

### 5.1 74HC138 = 拨码开关（3 根线换 8 个选择）

它用 **3 根输入线**（P2.5 / P2.6 / P2.7）决定 **8 个输出**（Y0–Y7）中哪一个有效，输出**低电平有效**。

CT107D 上的通道分配（这四个值要背下来）：

| 选通值 | 二进制（bit7..bit0） | 选中的外设 |
| --- | --- | --- |
| `0x80` | `1000 0000` | **Y4** → LED 锁存器 |
| `0xA0` | `1010 0000` | **Y5** → 蜂鸣器 / 继电器 |
| `0xC0` | `1100 0000` | **Y6** → 数码管位选 |
| `0xE0` | `1110 0000` | **Y7** → 数码管段选 |

- 为什么非要它：没有它，P0 只能同时伺候一个外设，LED 和数码管没法一起用。

### 5.2 74HC573 = 快递柜（关门后数据留着）

P0 只有 8 根线，却要分时伺候多个外设。锁存器的作用是：**把这一刻送进来的数据关在柜子里**。之后 P0 转去给数码管送数据，LED 那个柜子里的东西没动，灯照样亮。

- 为什么非要它：没有它，P0 上的数一变，所有外设跟着一起变，根本没法复用。

### 5.3 三步顺序不能变

```c
P2 = (P2 & 0x1F) | 0x80;   // ① 选通：保留低 5 位，高 3 位设成 100 → 打开 Y4（LED 柜门）
P0 = 0xFE;                  // ② 送数：最低位 0 → 第一颗 LED 亮（0 亮 1 灭）
P2 &= 0x1F;                 // ③ 锁存：高 3 位清零 → 柜门关上，数据留在里面
```

| 搞错哪一步 | 会发生什么 |
| --- | --- |
| 先送数、后选通 | 柜门还没开，数据送到了**上一次**打开的那个柜子（或压根没人接），LED 毫无反应 |
| **忘记第 ③ 步锁存** | 柜门一直开着 → P0 的任何后续变化都直接灌到 LED 上。你想让 LED 显示 A，它却显示你后来写给数码管的数，表现为**乱闪、该亮的不亮**。这是新手"灯不亮"最常见的原因 |

## 6. 手绘链路图怎么画

判据不是"画得像不像电路图"，而是**能否口述出信号流向**：

> 芯片先用 P2 的 3 根线告诉译码器要开哪个柜子 → 译码器选中对应通道 → 数据经 P0 送进去 → 锁存器关门记住它 → 外设按这个数据工作。

能不看笔记讲出这个顺序，就算完成。

## 8. 常见报错对照

| 报错 | 真实原因 | 怎么查 |
| --- | --- | --- |
| `error C141: syntax error` | 语法错误。90% 是漏分号、括号不配对，或**用了中文标点**（全角 `；` `（）`） | 看报错行号，往**上一行**找（分号常常漏在上一行末） |
| `error C129: missing ';'` | 明确缺分号 | 定位到行号补上 |
| `error L250: CODE SIZE LIMIT` | 代码超过 2KB，评估版限制 | 入门阶段不会遇到；真遇到就精简代码 |
| `warning C280: unreferenced local variable` | 定义了没用到的变量 | 可忽略 |
| `error: 'for' loop initial declarations are only allowed in C99 mode` | 在 `for` 里写了 `int i = 1`，而编译器用的是老标准 C90 | **把 `int i;` 提到 `for` 前面**（见下方说明） |
| 找不到头文件 / `P0` 未定义 | 器件型号没选对，或没 `#include` 对应头文件 | 重建工程并选 STC15F2K60S2 |
| 新建工程搜不到 STC15F2K60S2 | 器件库是 μVision **启动时**加载的 | 用 STC-ISP 挂库后**完全退出 μVision 再重开** |

### 8.1 为什么 `for (int i = 1; ...)` 会报错

在 `for` 里**顺手定义**变量（写成 `for (int i = 1; ...)`）是 C99 才有的写法。很多教学用的编译器默认按老标准 C90 编译，就会报：

```
error: 'for' loop initial declarations are only allowed in C99 mode
```

**建议直接改写法，不要去改编译器设置**：

```c
int i;                    /* 先声明 */
for (i = 1; i <= 10; i++) /* 再用 */
```

**为什么推荐改写法而不是改设置**：你后面要用的 **Keil C51 更接近老标准**，要求变量声明写在代码块的开头。现在养成"先声明、再使用"的习惯，将来写单片机代码一行都不用改。

（若坚持用 C99 写法：Dev-C++ 里 `工具` → `编译选项` → 找到「编译时加入以下命令」→ 勾选并填 `-std=c99`。）

## 9. Git：为什么每天都要提交一次

```bash
git add .
git commit -m "今天做了什么：例如 主线一 D2 位运算练习跑通"
git log --oneline
```

**为什么这件事不能补做**：战队考核的「积极程度」看的是提交时间戳。本地时间理论上可以改（`git commit --date`），而**推到 GitHub / Gitee 之后，时间由服务器生成，改不了**——所以远端仓库的证据强度比本地高一个量级。

- 不这么做会怎样：45 天后你拿不出任何"我持续投入过"的证据，而这一项恰恰是别人突击不出来的。

## 10. 先在 PC 上建立 C 的直觉（5 个练习）

**为什么要在电脑上先学一遍**：写单片机代码时，你唯一的反馈是底部一行 `0 Error(s)`——等于没有反馈。而在电脑上 `printf` 一下结果立刻出现，**反馈速度决定入门速度**。

先用 `D:\Dev-Cpp`（自带编译器，新建源代码即可跑）。每个练习**必须看到输出变化**再进下一个。

**① 顺序执行**
```c
#include <stdio.h>
int main() {
    printf("第一行\n");
    printf("第二行\n");
    return 0;
}
```

**② 变量是盒子**
```c
#include <stdio.h>
int main() {
    int i = 0;
    i = i + 1;
    printf("i = %d\n", i);
    return 0;
}
```

**③ 循环**
```c
#include <stdio.h>
int main() {
    for (int i = 1; i <= 10; i++) {
        printf("%d ", i);
    }
    return 0;
}
```

**④ 死循环（对照第 3 节）**
```c
#include <stdio.h>
int main() {
    int i = 0;
    while (1) {
        i = i + 1;
        printf("i = %d\n", i);
        if (i >= 5) break;
    }
    return 0;
}
```
电脑上必须靠 `break` 退出，否则一直刷屏；而单片机上没有"退出"这个概念，所以敢写裸的 `while(1)`。

**⑤ 一批数据（为流水灯做准备）**
```c
#include <stdio.h>
int main() {
    unsigned char led[4] = {0xFE, 0xFD, 0xFB, 0xF7};
    for (int i = 0; i < 4; i++) {
        printf("%d ", led[i]);
    }
    return 0;
}
```
这四个数就是将来流水灯的四个状态。

## 13. 关于 Visual Studio（VS，不是 VS Code）

**能用，但入门阶段不建议**。理由有三：

| 问题 | 具体表现 |
| --- | --- |
| 概念负担 | VS 要先建"解决方案"再建"项目"再加源文件，而 Dev C++ 是单个 `.c` 文件直接跑 |
| 编译器差异 | VS 用 MSVC，会把教材里的 `scanf` 报成不安全的 `C4996` 错误，要求改 `scanf_s`，与网课代码不一致 |
| 与课程不同步 | 翁恺课全程用 Dev C++，换工具会导致"你的界面和老师的不一样" |

**如果学校教材或机房要求用 VS**，也能用，只需两处处理：
- 项目属性 → C/C++ → 预处理器 → 预处理器定义，加上 `_CRT_SECURE_NO_WARNINGS`（这样 `scanf` 不报错）
- 新建项目选「空项目」，再手动添加 `.c` 源文件（**文件后缀必须是 `.c` 不是 `.cpp`**，否则按 C++ 编译）

**VS 什么时候值得用**：学到指针与数组越界时（9/28 之后），VS 的调试器可以单步执行并直接看内存地址，非常直观。Dev C++ 也自带调试功能（翁恺 P19 讲过），两者选一个即可。

## 14. C 语言英文速查表（每个词一句话）

**不用背**。用到哪个查哪个，一周之后自然就熟了。C 语言里出现的英文词总共就几十个，比英语课本少得多。

### 14.1 程序骨架

| 英文 | 读作 | 意思 | 在你代码里的角色 |
| --- | --- | --- | --- |
| `#include` | include（包含） | 把另一个文件的内容"拿进来" | `#include <stdio.h>` 就是把输入输出的说明书拿进来 |
| `<stdio.h>` | **st**andar**d** **i**nput **o**utput **.h**eader | 标准输入输出头文件 | `printf`、`scanf` 的说明书放在这里 |
| `main` | 曼 | 主函数 | **程序的入口**，芯片/系统从这里开始执行 |
| `void` | 沃伊德 | 空、无 | `void main(void)` = 不返回东西、也不收参数 |
| `return` | 瑞特恩 | 返回 | `return 0;` 把 0 交回给系统，习惯上 0 = 正常结束 |

### 14.2 输入输出

| 英文 | 意思 | 说明 |
| --- | --- | --- |
| `printf` | **print f**ormatted，按格式打印 | 输出到屏幕 |
| `scanf` | **scan f**ormatted，按格式扫描 | 从键盘读入 |
| `%d` | **d**ecimal，十进制 | 打印/读入整数 |
| `%c` | **c**har，字符 | 单个字符 |
| `%s` | **s**tring，字符串 | 一串字符 |
| `%x` / `%X` | he**x**，十六进制 | 小写 / 大写显示 |
| `%f` | **f**loat，浮点 | 小数 |
| `\n` | **n**ewline，换行 | 相当于敲一次回车 |
| `&`（用在 `scanf` 里） | address of | 取地址：把读到的东西放到这个变量的位置去 |

### 14.3 变量与类型

| 英文 | 意思 | 说明 |
| --- | --- | --- |
| `int` | **int**eger，整数 | 在 51 上是 16 位 |
| `char` | **char**acter，字符 | 在 51 上是 **8 位**，所以端口操作用它 |
| `unsigned` | 无符号 | 没有负数，只能表示 0 和正数 |
| `signed` | 有符号 | 默认，能表示负数 |
| `float` | 浮点 | 小数（51 上很少用，慢） |
| `const` | **const**ant，常量 | 定义了不许改 |
| `static` | 静态的 | 与作用范围/存储位置有关 |
| `sizeof` | size of，……的大小 | 求某个类型占几个字节 |

### 14.4 流程控制

| 英文 | 意思 | 说明 |
| --- | --- | --- |
| `for` | 为了/循环 | 计数循环，三个格子：起点、条件、步进 |
| `while` | 当……的时候 | 条件循环 |
| `if` / `else` | 如果 / 否则 | 分支 |
| `break` | 打断 | **跳出**整个循环 |
| `continue` | 继续 | **跳过本轮**，直接进下一轮 |
| `switch` / `case` / `default` | 开关 / 情况 / 默认 | 多分支选择 |
| `do ... while` | 先做……再判断 | 至少执行一次 |

### 14.5 符号

| 符号 | 意思 | 坑 |
| --- | --- | --- |
| `=` | **赋值**：把右边放进左边 | **不是数学的"等于"** |
| `==` | **判断相等** | 新手最常把 `=` 和 `==` 写混 |
| `!=` | 不等于 | `!` 读作 not |
| `++` / `--` | 自己 +1 / 自己 -1 | 见第 2 节说明 |
| `+=` `-=` | 自己 += 某数 | 复合赋值 |
| `&&` / `\|\|` / `!` | 并且 / 或者 / 非 | 逻辑运算 |
| `&` `\|` `~` `^` | 按位与 / 或 / 取反 / 异或 | 见第 4 节 |
| `<<` `>>` | 左移 / 右移 | 见第 4 节 |
| `0x` | 十六进制前缀 | 见第 2.2 节 |
| `//` | 注释掉这一行 | 编译器忽略 |
| `/* ... */` | 注释掉这一段 | 同上 |

### 14.6 报错里的英文

| 英文 | 意思 | 你该怎么做 |
| --- | --- | --- |
| `error` | 错误 | 必须解决，否则不会生成程序 |
| `warning` | 警告 | 可以先不管 |
| `syntax error` | 语法错误 | 看行号，先查上一行末尾有没有分号 |
| `expected ';' before ...` | 期望在……前面有个分号 | **上一行漏了分号** |
| `stray '\243'` | 出现了不该有的字符 | 多是**中文全角标点**，见第 8 节 |
| `undefined reference to ...` | 引用了没有定义的东西 | 函数名拼错，或文件没加进工程 |
| `declaration` / `redefinition` | 声明 / 重复定义 | 同一个变量定义了两遍 |
| `lvalue required as left operand of assignment` | 等号左边必须是变量 | 你写了 `i + 1 = i` 这类式子 |
| `unreferenced local variable` | 定义了没用的局部变量 | 可忽略 |
| `missing function-prototype` | 缺少函数原型声明 | 函数定义写在使用之后，或没 include 头文件 |

| 缩写 | 全称 | 意思 |
| --- | --- | --- |
| `hex` | hexadecimal | 十六进制（`0x` 开头） |
| `dec` | decimal | 十进制 |
| `bin` | binary | 二进制 |
| `bit` | binary digit | 位，一个 0 或 1 |
| `byte` | — | 字节，8 个 bit |
